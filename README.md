# YUAN BUILD OS v3.4

YUAN DESIGN BUILD 的施工管理系统源码。包含前端、后端、数据库迁移、构建脚本、48 项自动检查及可选的真实浏览器检查。

当前 v3.4 源码在原有业务流程上增加了可配置 AI 接口、决策建议、输入异常提示和响应式界面优化。仓库使用明确标记的演示工程与示意图，不包含原站点的私人项目数据。本地修改不会自动更新原在线系统，部署前仍需在自己的环境验证身份和存储绑定。

## 上传 GitHub

1. 解压源码包。
2. 创建 GitHub 仓库，把 `YUAN_BUILD_OS_v3.4` 文件夹里面的内容上传到仓库根目录。不要只上传 ZIP。
3. 确认仓库根目录能看到 `package.json`、`README.md`、`app/`、`tests/` 和 `scripts/`。

网页上传和 Git 提交均可。若网页上传没有包含隐藏的 `.openai/` 目录，构建脚本会自动从 `hosting.example.json` 生成配置。

## 本地使用

使用 Node.js 24 或更高版本。本工程没有第三方 npm 依赖，无需执行依赖安装。

```bash
npm run build
npm test
npm run validate
npm run preview
```

打开命令输出的本地地址。也可以直接用浏览器打开包内的 `index.html`，使用本机模式。

需要开发和验证完整 API 时，构建后运行 `npm run dev`。这个服务仅监听本机回环地址，使用固定的本地开发负责人身份，并通过 SQLite 模拟 D1 和 R2；数据保存在被 Git 忽略的 `.yuan-dev/`。它不是生产登录服务，不要公开暴露。启动后会使用演示项目，刷新和重启会保留本地开发数据。修改源码后重新构建；后端变更还需重启开发服务。

源码修改后重新运行 `npm run build`。`index.html`、`worker/index.js` 和 `dist/` 是构建结果，日常修改应在 `app/` 中进行。

## 恢复你的真实项目

在原系统的“项目与备份”中导出完整 JSON，再在新环境的同一页面导入。完整备份可恢复任务、材料申请、库存流水和进度记录。把源码放进 GitHub 不会自动复制线上数据库或员工/客户授权。

## 在线部署与身份要求

GitHub 仓库用于保存和管理源码。GitHub Pages 只能承载本机模式，不能提供本工程的数据库、文件存储和多账户协作接口。

完整在线版面向现有的 Sites / Cloudflare Worker 执行环境，需要：

- D1 绑定 `DB`，部署前应用 `drizzle/0000_workspace.sql`。
- R2 绑定 `BUCKET`，用于图纸和照片。
- 可信身份入口提供 `oai-authenticated-user-id` 和 `oai-authenticated-user-email`。现有实现依赖 Sites 在请求边界注入并保护这些身份信息。
- 私人访问边界必须在第一次访问时就生效，因为首次通过身份验证的账户会初始化负责人身份。

如果迁移到独立 Cloudflare、Vercel 或其他主机，需要先实现自己的登录与身份适配，确保客户端不能伪造身份头，再开放协作接口。应用内登记角色与网站访问授权是两个独立步骤。

部署参数中没有旧站点的 `project_id`。通过 Sites 新建项目时，应使用新环境返回的标识，不要借用旧站点标识。

## 已实现的流程

- 7 日计划与每日任务：草稿、发布、接单、开工、受阻、报告、验收。
- 48 小时和 7 日材料预测：按使用时间、净领用量及预计到货计算。
- 材料申请、负责人审批、下单、分批到货，以及盘点、领用、退回、损耗。
- 老板、工长、工人、客户四类权限；中文、西语、英语和印地语工人工作台。
- 公开客户进度、云端同步、完整备份、恢复点及并发冲突保护。
- 发布任务、采购审批和验收前显示规则检查；配置 AI 后异步给出建议，不自动提交业务决策。
- 异常面积比例、数值大幅变化、采购数量和单价、预算、迟到订单与进度倒退提示。负数、空白、无效日期等硬错误由表单或业务校验拦截。
- 客户侧四语言进度解释；AI 仅接收该账户有权查看的公开进度，负责人预览客户页同样使用公开投影。
- 表单编辑期间暂停自动刷新；保存防重复提交、离线保存及联网同步；手机表单、采购弹窗和看板适配。

## 配置 AI API

支持 HTTPS 的 OpenAI Chat Completions 兼容接口。配置位于服务端，不通过浏览器或备份保存密钥。未配置时所有本地规则及原业务流程仍可使用。

| 服务端变量 | 用途 | 示例 |
| --- | --- | --- |
| `AI_BASE_URL` | API 根路径，程序自动追加 `/chat/completions` | `https://api.openai.com/v1` |
| `AI_MODEL` | 服务商支持的模型名称 | `gpt-4.1-mini` |
| `AI_API_KEY` | 服务端密钥绑定 | 通过环境设置安全填写 |

本地开发可把 `.env.example` 复制为已被 Git 忽略的 `.env`，在本机安全填入配置，然后运行 `npm run dev`。不要把真实密钥放入示例文件、源码或聊天。线上在 Worker / 托管平台绑定同名变量和 Secret。使用其他兼容服务商时同时修改 API 地址、模型、网络允许域名及密钥允许的目标域名。无需把 AI 服务域名加入浏览器 CSP，因为调用来自后端。

配置后，关键决策和客户页自动分析；明显异常的项目输入及采购审批调整会经防抖后分析。负责人未保存的预案仅允许有限数值字段，标记为未提交，不写入数据库。AI 使用精简上下文，不发送图片、协作账户列表和成员邮箱字段。客户不能提交内部决策预案或分析其他项目。

接口：`GET /api/ai/status` 检查是否配置，`POST /api/ai/advice` 提交 `{projectId, language, focus, focusId?, question?}`；`focus` 为 `overview`、`publish`、`approval`、`review` 或 `customer`。接口沿用现有身份和项目授权。负责人可额外提供受限的 `proposal.project` 数值或 `proposal.purchase` 明细进行只读分析；不接受浏览器提供的任意工作区作为模型上下文。

每次上游请求 10 秒超时，相同分析合并并缓存 2 分钟，每个 Worker 实例对同一账户最多发起 8 次/分钟，最多并行 8 次。多实例生产部署若需要全局配额，应在网关配置共享限流。AI 故障、限流或响应异常时返回规则结果；不自动重试付费分析。读取业务接口仅在临时故障时重试一次。提示仅供核对，实际价格、工期和验收仍由负责人确认。

## 检查范围

`npm test` 的 48 项检查覆盖业务逻辑、迁移、角色权限、并发、AI 上下文隔离、兼容请求、超时、限流、缓存和降级。AI 自动测试使用模拟服务商响应，不代表真实密钥或具体模型已通过验证。

可选的真实浏览器检查：环境需提供 Python Playwright 和 Chromium，然后运行 `python3 tests/browser_smoke.py`。该脚本启动隔离的临时开发服务，验证任务生成和同步、未保存表单保护、重复提交、离线恢复、客户解释及 360/768/1440 像素下 8 个页面和材料弹窗的布局。检查不访问付费模型，不修改你的开发数据库。当前版本已在 Chromium 中通过这些检查；它不代替 Safari/iOS 真机或生产环境验收。

PDF 提取会按需加载现有 PDF.js 组件，需要网络；ASCII DXF 和手动标注可在本机使用。PDF/DXF 结果是待人工核对的候选点位。
